# galtools

galgame 解包资源的处理工具箱。一个 GUI 窗口作为统一入口，工具本身仍可单独在命令行使用。

```
python run_gui.py
```

左侧按分类列出工具，右侧是根据工具声明自动生成的参数表单，底部是所有工具共用的进度条与日志。

## 安装

需要 Python 3.10+（实测 3.10.8）。GUI 依赖 PySide6，「vndb 声优出演表」与「声优库」写 Excel 依赖 openpyxl：

```
pip install -r requirements.txt
```

`galtools/core/` 只用标准库，工具也不在 import 期碰第三方库（openpyxl 一律在函数内 import）。因此没装 PySide6 时 GUI 起不来但命令行照常可用，没装 openpyxl 时工具列表照常列出——两点都有测试钉住，`requirements.txt` 里也逐行注明了哪个依赖是给谁的。

## 现有工具

**Majiro 脚本文本提取**（`galtools/tools/mjo_text.py`）把 arc_conv 解包出的 `.mjo` 批量提取为 txt，另在输出目录的父目录写一份合并全文。不递归子目录。

```
python -m galtools.tools.mjo_text <.mjo 目录> [输出目录]
```

输出目录留空时为 `<.mjo 目录>/script_text`。目录里一个 `.mjo` 都没有时什么都不做；有文件但全部解析失败时同样返回失败且保留旧合并全文。单文件文本与合并全文都先写同目录唯一临时文件再替换，写入异常或最终提交前取消不会留下半文件；取消前已经发布的单文件照常保留。

字节码起点按头部算出的 `header_len` 而不是硬编码的 `0x28`：入口函数表项数为 1 时两者相等（剧情脚本几乎都是），不为 1 的那些 UI 脚本旧起点会从入口表中间起步。但实测两部作品共 306 个脚本、其中 60 个项数不为 1，两种起点的提取结果逐条相同——入口表里的字节极少凑成文本 opcode，凑成了也过不了校验，逐字节步进会在遇到真 opcode 之前重新对齐。所以这不是一个曾经产出乱码的 bug，改它只是为了不依赖这种巧合；对账脚本是 `tests/manual/mjo_offset_diff.py`。

**语音时长筛选**（`galtools/tools/audio_filter/`）按时长区间把语音复制到源目录下的新文件夹，并生成复制清单。不解码音频，直接读 WAV 的 RIFF 头与 Ogg 的 granule position。

```
python -m galtools.tools.audio_filter.cli
```

命令行版是原来的五步交互向导，提示词与打印格式逐字保留。GUI 里那个「报命中数 → 确认 → 回退重设阈值」的循环由实时预览取代：改阈值立刻看到命中几个、多少 MB、磁盘够不够；NaN/Inf 会与非正数一样被拒绝。WAV 只接受物理 payload 完整的 PCM，截断块和非 PCM 编码计入解析失败；Ogg 被截断到几十字节、在头部切片上抛 `struct.error` 时也只算它自己失败，不会掀掉整次扫描。复制清单与两类失败清单都原子发布，写不成会明确列入失败且不报告不存在的路径；取消保留已经复制的文件，不继续发布后续清单。

**vndb 声优出演表**（`galtools/tools/vndb_voiced/`）抓 VNDB 上某个声优配过的全部角色，攒进本地库，也可以直接导出一个工作簿：一页概览（各人的作品数、角色数与主次分布）+ 每人一页明细，标题与角色名都带指向 vndb.org 的超链接。填两人以上时额外算出共同出演的作品，旧仓库里这是另一个需要先跑两遍再手动喂两个 xlsx 的脚本。

「存入本地库」与「导出 Excel」是两个独立开关，GUI 里默认存库、不导出：进了库的人用下面那个「声优库」随时能离线导出，为了一份表格重抓几分钟没有道理。库目录与导出目录是两个字段，库里只躺 `s<id>.json`，导出物不进去。两个开关都关掉是矛盾配置，`validate` 直接拦下并置灰「开始」，不静默兜底；勾了开关却没填对应目录同理。先写库再写 xlsx——抓了几分钟，不该因为目标文件正被 Excel 占着连库都没进；库是一人一个文件，某个人写失败也只报他自己。

两个目录不对称：导出目录容许现建（命令行的 `-o` 指到哪儿就建到哪儿，见下面失败路径那段），库目录必须本来就存在。打错一个字不该悄悄开出第二个库来——那种错要等到发现数据分散在两处时才看得见。只存库、不导出的那一次连导出目录都不碰。

三人以上时两两及以上的每个组合各出一页——三个人就是「三人都在」加三种两人搭配共四页，没有交集的组合不建表。页名是组合内各人的罗马音，但 Excel 只给工作表名 31 个字符，三个人的完整罗马音塞不下（`Ono Ryouko+Mizuhashi Kaori+Okajima Tae` 是 39 个），所以整组一起降级：完整罗马音 → 姓 + 名首字母 → 姓 → sid，取第一个塞得下的。完整名字与「哪张表」的对应关系在新增的「组合」索引页里，那一页还带跳转链接。文件名把每个人的罗马音都写进去（`共同出演_Ono_Ryouko_Mizuhashi_Kaori_Okajima_Tae_3人.xlsx`），太长才退回前两人 + 等N人。

人数上限 8：N 个人有 2^N−N−1 个组合，8 人最多 247 张工作表，再往上只会产出没人翻得动的文件。同一个人填两次（`s367, Ono Ryouko` 是两个字串、一个人）按 sid 合并，不会抓两遍也不会出「他和他自己」那张表。

```
python -m galtools.tools.vndb_voiced.cli [目标...] [-o 输出目录或 .xlsx] [--db 库目录] [--no-export] [--refresh]
python -m galtools.tools.vndb_voiced.cli --update-all --db 库目录
```

命令行的默认与 GUI 刻意相反：不带 `--db` 的调用只导出 xlsx，与旧脚本一模一样；`--db 目录` 追加存库，再配 `--no-export` 就只存库。`--refresh` 忽略本次会话缓存重新抓取；`--update-all --db 目录` 不接目标、不导出 Excel，而是重抓库内所有人并只覆盖有变化的 JSON。默认值两边不同，但规则只有一份——`check_targets` 与 `check_options` 都转发给同一个 `validate`，只豁免导出目录那条存在性检查（命令行的输出目录一向是现建的）。参数不对时按 `ap.error` 以 2 退出，一个请求都不打。

目标可以是 id（`s367`）、声优页网址或名字，多个用逗号分隔；不带参数则进入交互模式。名字搜索会翻完全部候选页，跨页按 sid 去重后再判断是否只有一个精确命中；有歧义时不会替你猜，而是列出候选各自的主名并要求改填 id——按搜索结果的第一条自动取会静默选错人（实测搜 `Ono Ryouko` 会同时命中另一个人的某个别名行）。

走官方 kana JSON API（只用标准库 `urllib`），带限流、退避重试与三阶段字段裁剪。建连失败和响应体读取期的超时、连接重置、`IncompleteRead` 都会重试；响应不是合法 JSON 则直接报错，不把确定的数据错误当网络抖动。角色名来自便宜的 `/character` 查询，在 `/vn` 上展开 `va.character.name` 会让同样 100 部作品从 2 秒变成 30 秒。组合也不是每个各算一遍交集（那是 2^N 次全量遍历）：一次遍历得到每部作品的出演者集合，再只枚举这个集合自己的子集，而一部作品通常只被两三个人共享。

失败的路径也照「别让用户白等」来安排。要导出时，导出目录在抓取之前就先建一次：`-o Z:\nope\deeper` 以前要等打完 5 个请求才炸在 `os.makedirs` 上，几分钟的抓取白费，现在是零请求返回一句话。JSON 与 XLSX 都先写同目录唯一临时文件再 `os.replace`；进程内写入异常或提交前取消不会破坏旧正式文件，也不会报告未发布的工作簿。现存目录优先于 `.xlsx` 后缀，所以名为 `folder.xlsx` 的目录仍是目录。抓完才写不出去（盘满、整条路径过 260、目标正被 Excel 占着）报成一句话而不是一段栈，抓回来的东西还在会话缓存里，换个目录再点一次「开始」不必重抓。命令行有任一输出路径即以 0 退出，即使同时有部分人员失败；一个文件都没写出来时以 1 退出，`ap.error` 那类用法错误是 2，Ctrl+C 是 130。warnings 与逐项 failures 都写到 stderr，不会只在 GUI 里看得到。某个人抓失败时整份结果不进缓存——否则再点一次「开始」是零请求、同一份残缺结果，除非用户想到去勾「重新抓取」。撞上官方限额（这里按 190 请求 / 5 分钟留了余量）要等 5 秒以上时，日志里会说一声等多久；限流窗口挂在 `ctx.session` 上，也就是跨线程共享的，记账整段在一把模块级锁里做。

GUI 里查询前先摆一张「将要抓取」的表，ID 一列双击即可在浏览器里核对是不是这个人；名字有歧义时这张表换成全部候选，比预览框里只放得下的前几行好选。跑完把共同出演（三人以上是全员那一档，只有一个人时是他的全部出演记录）铺成表格，核对几部作品不必再开 Excel；各组合各自多少部则列在摘要里。后台始终只有一个活动任务：新预览或运行会请求取消旧任务，并等旧线程真实退出后才启动；隐藏页预览和旧 Qt 队列事件由页面与 token 双重隔离。关闭窗口同样异步等待，不阻塞界面；取消结果仍展示已经产生的路径、警告、失败和表格。

**声优库**（`galtools/tools/seiyuu_db.py`）离线翻上面那个工具攒下的库，从不联网，唯一的写操作是导出。两个筛选框决定屏幕上摆什么：都空是名册（库里每人一行，列与工作簿的「概览」页同一组，末尾多一列抓取时间，用来看谁的数据旧了该重抓）；只填关键词是跨全库搜索，逐条记录过一遍再按人聚合；只填人时一个人摆他的明细、两人以上离线算共同出演；两个都填就先按人筛再按关键词筛。点「开始」把屏幕上这一份写成 xlsx。

搜索看作品名、角色名、As 与 note，日文与罗马字两版都看，忽略大小写与空格，所以一个词无论用哪种写法都找得到。刻意不含 Role 与发售日：`main` 会命中半个库，日期用不着模糊匹配。两个筛选框一起用时有一处不对称：全库搜索里一条都没命中的人不摆（几十行「0 条」没有信息量），点名要看的人即使 0 条也留在表里，否则他会以为是自己填错了。

「只看这些人」三档匹配，只在前一档一无所获时才降级：sid → 名字精确相等 → 名字含这个词。最后一档命中多个是常态（在真实库里 `ryouko` 就同时命中小野 涼子和田中 涼子），此时不猜，而是列出候选要求改填 id——猜错了导出的就是另一个人的表，而这种错在表格里看不出来。填了人却一个都没对上时退回名册：用户要的人不在库里，此刻该让他看见库里到底有谁。人数上限 8 与抓取工具共用 `too_many_people` 一份规则：贵的不是抓取而是写出 2^N 张工作表，两边的门槛没有理由不一样。

没有 rescan 字段，改任何一格都自动重跑预览。读库很便宜（真库实测 54 人 / 6.6 MB / 1.7 万条记录，读 + 解析 95 毫秒，且预览跑在后台线程里），比起缓存住再操心「预览之后库又被抓取工具改过了」，每次重读更简单也更准。「导出目录」空着不算错——它进 `validate` 会连预览一起拦掉，那就连翻都翻不了，所以由 `PreviewResult.ok=False` 把「开始」置灰，表照旧铺出来。也不提供命令行：这个工具的产出就是屏幕上那张表，而导出用的是抓取工具已有的 `--db` 那条路。

选人导出沿用抓取工具的文件名：同样几个人，离线导出与在线抓取落到同一个文件名上，且逐格产出相同（`tests/test_seiyuu_db.py` 拿假 vndb 一次抓取同时产出两边再逐格比；真库上也对过一次，9 张页、5 万余格的值与超链接全同，差异只有 4 格 Role——那是 vndb 上游改了角色主次）。名册与搜索没有对应的在线产出，各自一种写法（`声优库_3人.xlsx`、`声优库_搜索_beta.xlsx`；关键词要过一遍 slug 并截到 40 字，整条路径过 260 会被一堆 Windows API 拒绝）。名册导出不带「组合」索引页：50 个人有 2^50 个组合，根本不算——`xlsx.build` 因此看的是 `combos` 是否为空而不是人数，只看人数会多出一张只有表头的空页。

屏幕上这四张表（名册、搜索命中、单人明细、共同出演）都由 `vndb_voiced/tables.py` 摆，抓取工具跑完显示的是同一份代码。同一批数据从网上抓回来还是从库里读出来，摆在屏幕上该是同一张表；两边各写一份的话，改动只会落到其中一边。角色主次的数法同理，由 `model.role_counts` 一份供工作簿的「概览」页与名册共用。

### 库的格式

`galtools/tools/vndb_voiced/store.py`，只用标准库。一人一个 `s<id>.json`，`indent=2` 且不转义非 ASCII——这个目录是用户会自己打开看的。顶层是 `schema` / `sid` / `name` / `original` / `fetched_at` 加一个 `credits` 数组，每条含 `vid title title_ja released cid cast cast_ja alias alias_ja note role` 十一个字段（与 `model.Credit` 同名，`CREDIT_FIELDS` 刻意写成常量而不是从 `dataclasses.fields` 现推：给 `Credit` 加字段就该顺手决定库格式跟不跟，有测试在忘了这件事时失败）。别名表不落盘：它只在抓取期用来把 aid 翻成 As 列，翻好的文本已经在每条记录里。

写是整份覆盖，先写同目录的唯一临时文件再 `os.replace`——进程内编码、写入或替换失败时旧正式文件不动，失败只清理本次写者自己的临时文件；这不是对断电时文件系统行为的额外保证。读的容错按「用户会手改这些文件」来定：认不出的键忽略、缺的键取默认值、非字符串退回空串（库的读者会对这些值 `casefold`、`strip`，`None` 进去就是一段栈）。`schema` 比工具新则拒读并说清是哪个版本。只认 `s<id>.json` 这一种文件名，文件名是身份来源；内部缺失或非法 sid 会按文件名恢复，但另一个合法 sid 与文件名冲突时拒读，不能悄悄串到另一人。库目录里躺着导出的 xlsx 或写崩的临时文件是常态，它们不该被当成库的一部分。一份坏文件只报它自己，库是攒起来的，其中一个人的文件坏了不该让整个查看器什么都显示不出来。

`sid` 是文件名的唯一来源，所以只认 vndb 那一种形状（`^s\d+$`），`../s1` 这类值在写之前就被挡下。

## 加一个新工具

往 `galtools/tools/` 放一个模块并暴露 `TOOL`，GUI 下次启动就会列出它。不需要改 GUI 任何一行。单个 `.py` 和子包（`__init__.py` 暴露 `TOOL`）两种形态都认——单文件是快车道，工具长大了再拆包。以 `_` 开头的模块会被跳过。

```python
import os

from galtools.core.spec import DIR, Field, RunResult, ToolSpec


def run(params, ctx):
    names = os.listdir(params['src'])
    for i, name in enumerate(names, 1):
        ctx.check_cancel()
        ctx.progress(i, len(names))
        ...
    return RunResult(summary='处理了 %d 个文件' % len(names),
                     output_paths=[params['src']])


TOOL = ToolSpec(
    id='my_tool', name='我的工具', category='文本',
    description='一句话说明，会显示在标题下方和树的悬浮提示里。',
    fields=(Field(key='src', kind=DIR, label='源目录'),),
    run=run,
)
```

`Field.kind` 只有 `dir` / `bool` / `number` / `text` 四种，由 `gui/form.py` 的分派表决定用哪个控件。要加新种类就往那张表加一个构造函数。`dir` 字段自带浏览按钮、拖放，以及按「工具 + 字段」分别持久化的最近路径下拉——在多个游戏目录间来回切换时省下反复粘贴长路径。`text` 字段默认是单行输入框，写 `history=True` 就换成同款下拉（vndb 那个声优框用它记住查过的人）。

目录历史在两个时刻写入：点「开始」时记全部有历史的字段（`remember_paths`），预览成功时另记其中真实存在的目录（`remember_dirs`）。后者是给「只看不导」那类用法的——翻库、看统计从不点「开始」，光靠前者路径每次开界面都得重新粘。预览是敲字过程中自动触发的，所以 `remember_dirs` 只写 QSettings、绝不碰控件：`remember_paths` 那套「清空下拉项再重填」会把光标从用户正在输入的那一格里踢出去。

`ctx` 是 `RunContext`（`galtools/core/context.py`），提供 `log(msg, level)`、`progress(done, total, note)`、`check_cancel()` 和 `session` 字典。GUI 传的实现把这些转成 Qt 信号，命令行传 `ConsoleContext`。

三个可选钩子：

`preview(params, ctx) -> PreviewResult` 在参数变动后自动调用，把摘要显示在预览框里。`ok=False` 时禁止启动——磁盘不够、命中 0 个都靠它挡下。工具没什么可预览的就不实现，预览框自动隐藏。

`PreviewResult` 与 `RunResult` 都可以再带一个 `Table(columns, rows, title)`，GUI 在预览框下方铺一张表：点表头排序、Ctrl+C 按 TSV 复制选中区域，单元格写成 `(文本, 链接)` 二元组就变成双击打开浏览器的蓝字。数字传 int/float 而不是字符串，否则 `10` 会排在 `9` 前面。不给表就不显示，纵向空间还给上面的表单。

`validate(params) -> [(字段 key, 错误消息)]` 校验不通过时「开始」按钮禁用，消息标红显示在对应字段下方；key 填空串表示整表级错误，显示在表单末尾。跨字段规则（如「上限必须大于阈值」、「勾了存库就得填库目录」、「两个开关不能都关」）只能写在这里，`Field` 上没有 min/max 常量。命令行入口要自己调它——`vndb_voiced/cli.py` 的 `check_targets` 与 `check_options` 就是把两半参数分别转发给 `validate`；`audio_filter` 那个交互向导目前是另写一份等价规则，两处漂移的风险仍在（vndb 的人数上限当初就是这么漏掉命令行的）。

一个坑：`validate` 报错会连预览一起拦掉（`_request_preview` 见到错误就直接返回）。所以「填了才有意义」的字段必须写成 `required=False` 加一条 `validate` 规则，写成 `required=True` 会让用户在填完它之前连预览都看不到。声优库的「导出目录」正是这一类：它空着时只该置灰「开始」，不该拦住翻库；vndb 那两个「勾了才必填」的目录同理，写成必填的话没勾的那一个也会挡住预览。

`Field.rescan=True` 声明「改这个字段会让预览赖以计算的数据集失效」。此时 GUI 不自动重算，只把预览标记为过期并露出那个按钮——否则在路径框里敲一个字符就会去 walk 一遍整个盘。改非 rescan 字段则防抖 300ms 后自动重算。数据集缓存放 `ctx.session`，由 GUI 按工具持有。按钮上的字由 `ToolSpec.scan_label` 决定，默认「扫描」；vndb 那个叫「查询」，它打的是接口而不是磁盘。

取消靠 `ctx.check_cancel()`，它抛 `Cancelled`。**`Cancelled` 继承 `BaseException` 而不是 `Exception`**，这样批量循环里的 `except Exception` 不会把取消吞成「单个文件失败」然后继续跑完。要向 GUI 汇报已完成的部分，就在放行异常前给它挂一个 `RunResult`：

```python
except Cancelled as c:
    c.partial = RunResult(summary='已复制 %d / %d 个' % (copied, total),
                          output_paths=[out_dir])
    raise
```

某个工具 import 失败只会让它自己缺席：树里显示成「加载失败」、栈写进日志，其余工具照常可用。

## 测试

```
pytest
```

覆盖四个工具的纯逻辑、registry 的容错，以及 GUI 里几个「坏了也没人喊」的分支。`pytest.ini` 里的 `pythonpath = .` 让 `galtools` 无需安装即可导入。vndb 那套测试零联网：`api` 模块只留 `_open` / `_sleep` 两个注入点，测试全打这两处（假睡眠顺带推进一个假时钟，否则限流的滑动窗口永远滚不过去）。库的测试同样零联网、零真实用户状态，库一律建在 `tmp_path` 下。

`test_seiyuu_db.py` 里有一条跨工具的对拍：用假 vndb 跑一次抓取，同时产出在线的工作簿和本地库，再从库离线导出同样几个人，逐格比页序、表名、每格的值与它指向哪里。库里漏存了字段、读回来串了行、组合顺序变了，都只在这里显出来——两条路径各自的测试都只跟自己比。

`tests/test_gui.py` 顶上是 `pytest.importorskip('PySide6')`，没装 Qt 就整个文件跳过——命令行用法不该因为缺 Qt 连测试都跑不了。它离屏跑，钉这几件事：活计换代后被放弃的线程发的日志、进度、结果一律丢弃；取消时挂在 `Cancelled` 上的 `partial` 要送到 `run_cancelled`；预览失败后进度条要从无限滚动收回来；预览成功要把目录记进历史、且不能扰动正在输入的那一格；路径被剥到只剩盘符时要把分隔符补回去（`E:` 指的是该盘的当前工作目录而非根目录，`isdir` 却照样为真，产出会静默落到别处）。这些位置的变异在写测试之前都能全绿通过。

更完整的一轮留给 `tests/manual/` 里的手动脚本：`testpaths = tests` 只收 `test_*.py`，这几个不会被 pytest 捡走，要跑就 `python tests/manual/gui_smoke.py`。`gui_smoke.py` 离屏起真窗口走完「选工具 → 查询 → 预览 → 开始 → 改参数 → 重开窗」一整轮，vndb 那层换成测试里的假接口；同一轮里存进去的那个库接着换「声优库」翻一遍，只预览、不点「开始」，再开第三次窗口确认库目录照样被记住。`gui_widgets.py` 造一个假工具钉住整表级错误与表格的排序、链接、复制——整表级规则现在真有一条（vndb 那边「两个开关都关掉」），但它要联网才走得完一轮；`vndb_live.py` 是唯一真联网的一个，拿真实 s367 与实测基准对账——接口哪天改了字段，只有它能发现；`mjo_offset_diff.py` 要一批真 `.mjo` 才有意义，用来复核字节码起点那条结论。

前两个脚本都把 `main_window.QSettings` 换成临时 ini（`tests/test_gui.py` 同理）。PySide6 里 `QSettings(org, app)` 不看 `setDefaultFormat()`，照样写注册表，不换会把验证用的路径写进用户的真实配置。
